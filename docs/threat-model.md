# POC 威胁模型与未完成边界

## 信任边界

用户通过 UI 建立 Task/Recipe 分享授权。目标 App 文本、历史标题、截图和本地模型输出均为不可信数据。模型置信度不构成授权。禁止任意 Intent、shell、URL、支付、删除、账号切换、自动授权和上传文件。

Guardrail 检查当前任务、步骤和预算；目标必须是当前步骤的获准参与者。写入 / 提交要求当前观察绑定的 thread 证据，payload 必须与程序从冻结来源重新构造的正文、来源、接收者和哈希完全一致。写入已经跨 App 边界，不把提交按钮当成唯一外发点。

生产中的 thread / 节点角色证据必须来自独立、版本绑定的确定性核验器。目前该核验器尚未完成，AppHints 一律返回未验证，PhoneTools 没有真实效果执行器。不能仅因一个调用方自行构造 `ThreadEvidence` 就认为证据可信；后续接入时需收窄构造与执行接口，完成代码结构约束及测试后再开放副作用。

## 当前限制与残余风险

- 未执行安全测试。Guardrail 纯函数已实现，但不能宣称“已经证明不可绕过”。当前没有可绕过的 Android 写入/发送入口，因为这些入口尚未实现。
- task/turn/payload/thread/journal 数据模型和恢复暂停已实现。真实 write-ahead intent、执行与结果事务尚待执行器接入；不能宣称已具备崩溃后自动恢复。
- Room 快照当前将消息和 payload 放在任务 JSON 内，适合早期小任务；大量长回答需要后续迁移消息表，保持单一权威写入源。
- 屏幕观察有限长且无消息角色识别，不能作为完整回答转发。长回答的滚动拼接、顺序、首尾和格式完整性均未实现。
- 无障碍授权权限广，第三方 UI 可变、伪装与语义歧义仍存在。包名白名单无法证明节点安全。
- 窗口截图仅 API 34+；不做 OCR 正文重构。暂停或清除观察后不能继续执行旧引用。
- 本地模型原生解析第三方权重文件，用户应从可信来源取得；SHA-256 只证明匹配预期文件，不证明文件本身无害。
- 首次 task thread 创建/绑定尚无可信流程。不能用模型声称“新会话为空”解锁首次外发。
- 不承诺 exactly-once。SUBMITTING 或遗留 pendingIntent 恢复后只会暂停，找不到屏幕消息不等于没有发送。
- 现有实现没有恢复授权 UI；不会让“继续”按钮未经核验就重新提交。

## 后续开放真实执行的前置条件

每款具体版本都需要真实控件样本、thread 首/最近 user message 的角色及位置核验、精确输入回读、发送消息确认和完整回答抓取。执行前保存 intent，并在统一入口重新读取任务修订号、取消状态、预算和新观察；任一条件变化都拒绝。每步只允许一个待决副作用。

准入条件要写成代码和测试；不能将“暂时不启用”误写成已完成整个安全机制。
