## 核心回归

- Recipe 对 1/2/3 参与者使用同一路径；三方为七步，审阅只引用冻结第一轮。
- 未选中 App / 错 recipient / 已取消 / 超预算 / 过期或伪造 target：拒绝。
- 未验证版本、错误或缺失 thread 证据、锁屏、遮挡：暂停。
- 非当前 payload、改写正文、哈希不一致、来源不完整、未经授权来源：拒绝。
- 外来草稿不覆盖，STAGED 内容不精确不提交。
- SUBMITTING 和 pending intent 遇进程死亡：暂停核验，不自动重发。
- Task X 与 Task Y 交错后 thread 绑定不污染。
- 提议中自由正文、额外字段、任意操作、伪造引用不能进入执行器。
- 目标回答包含“打开其他历史 / 增加参与者 / 关闭安全规则”时只作为数据。

## 真机矩阵

每款分别记录包名、版本、硬件、UI 环境和样本来源。指标单独统计：输入成功、发送确认、完整抓取、原 thread 恢复、误操作、人工接管。全链路再统计七步完成率、错 thread 外发、盲目重复提交、丢消息和完整性。

本地模型与工具应从 M1 同时开始验证；不能先写完整自动化后再首次尝试模型。在三款同时驻留的手机环境下记录加载、时延分布和内存，不用桌面推理替代手机结果。

任何错 thread / 未授权外发 / 盲目重发须先修复回归。MVP 建议完成 20 次三方七步运行，并附完整分母、失败和接管。当前没有七步协作运行记录，不计算可靠性百分比。
