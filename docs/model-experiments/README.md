# 手机本地模型实验 — 2026-09-22

设备：23013RK75C / SM8475 / Android 15 / 系统 RAM 7,354,276 KiB。
模型与 SHA-256：见 ../model-lock.json。手机上的 App 通过进程内 JNI 执行，无网络权限，无电脑或云端模型代答。电脑只负责构建、安装、打开 App、触发同一实验入口及收集脱敏指标。

任务固定为：定位当前可用的聊天文本输入框；找不到或不确定时 PAUSE。输出仅允许 FOCUS_INPUT / PAUSE 和已提供的节点引用，不执行任何提议。单次快照不代表完整自主导航或协作能力。

记录 01–05 的 prefill 错误当时统一记为 MTMD_PREFILL_FAILED，耗时接近内置 90 秒取消边界；后续版本将取消/超时单独标记 CANCELLED_OR_TIMEOUT。不能把这些失败算成识别成功。

Kimi 当时处于语音模式，快照没有 editable 节点，PAUSE 与此相符。DeepSeek 2.5.2 首页有可见的“发消息或按住说话”入口，但快照没有 editable 节点；PAUSE 只能证明拒答路径和 JSON 解析工作，不能证明成功定位。

load_ms=0 表示复用模型实例。PSS 每 250 ms 采样，不是精确系统峰值；各次运行受驻留页、温度及其他 App 影响。样本量不足以报告准确率或性能分位数。

原始截图及节点正文不进入报告。文件只保留包名/版本、耗时、PSS、错误、提议及节点结构属性。未发送目标 App 消息。

## 第二阶段：手机专用 ARM 指令构建

最终构建开启 -O3、armv8.2-a+dotprod+fp16+i8mm；所有 CPU 的系统特性均已核对。APK SHA-256：`c2bda9c204a6bb6860f3c89282a95ea0100ded3a50287748d9ce3e2e238d891d`。不保证这个专用 APK 在缺少上述指令的手机上运行；项目默认仍为通用 armv8-a。

调试版增加 DUMP 权限保护的单次观察触发，复用 InspectionService 的包名、窗口、锁屏、时限和截图边界；避免先切回本 App 导致待测输入框收起。不是模型导航或点击。

- 07：DeepSeek 空白输入框由调试者手动展开，直接采样 42 节点，其中 1 个 editable。小模型在手机上返回 FOCUS_INPUT，选中该 editable 节点，原屏幕 bounds 为 `74 1380 1001 1440`，与键盘上方文本输入区匹配。冷加载 7.951 s，节点推理 26.305 s，采样 PSS 峰值 2,229,055 KiB。证明一次输入框定位成功，不代表自主展开、点击或发送成功。

- 08：对 07 的同一份快照增加窗口截图，手机模型仍返回相同 FOCUS_INPUT 节点。复用已加载实例，推理 37.004 s，采样 PSS 峰值 2,292,105 KiB（约 2.19 GiB）。这是“节点 + 截图”的联合输入，不是截图单独识别实验，不能据此证明模型完全依赖视觉。

## 本轮结论

已证实：官方模型文件在手机校验通过；进程内 CPU/JNI 可加载；有一次明确输入状态下的节点定位正例，以及同一快照的节点加截图正例；Kimi 语音状态下能返回暂停。

尚未证实：自主找到/启动 App、切换输入模式、纯视觉定位、实际点击/输入/发送、三方完整协作、跨版本稳健性和成功率。当前 26–37 秒的单步延迟仍偏慢；这些数据不是整体任务完成率。

本轮未执行单元测试套件，执行了 native/Kotlin APK 构建、release 权限检查及上述实机实验。

实验结束后已通过 App 的“卸载模型实例（保留文件）”释放 native 模型。系统查询 TOTAL PSS 降至 175,775 KiB；无障碍仍连接、armed=false，临时观察已清空。模型文件、最终 APK 和脱敏实验记录保留，临时调试截图已删除。
